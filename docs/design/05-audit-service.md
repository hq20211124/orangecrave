# 05 · 审核与客服

## 1. 为什么审核是本系统的重中之重

橙刻的业务是**用户上传图片、公司印刷成实物并交付**。这意味着：印侵权图，平台要担责。

与「用户自己在社交平台发图」不同，这里是**平台参与制造和流通**。所以审核不是可选功能，是**唯一能挡法律风险的环节**。

同时它又是转化率的敌人——审得太严用户流失，审得太松平台担责。本设计的目标是**让机器挡掉大部分，人只看少数**。

## 2. 三层审核

| 层 | 触发 | 端点 / 字段 |
|---|---|---|
| **图片审核** | 上传即审 | `file/auditImg` |
| **文本审核** | 作品名、备注输入 | `needAudit: true` |
| **作品审核** | 作品整体状态 | `workStatus` |

### 2.1 图片审核

**自动 + 人工两层**：

```
上传
  │
  ├─ pHash 比对黑名单 ──命中──> 直接驳回，不进人工队列
  │
  ├─ 机器审核（违规内容识别）
  │      ├─ 明确违规 ──> 驳回
  │      └─ 疑似 ──────> 进人工队列
  │
  └─ 通过 ──> 进入人工队列（抽检或全检）
```

**两层的理由**：

- 全自动挡不住新图（模型有盲区）
- 全人工审量大会累死人且容易漏
- **黑名单命中直接驳回**是最廉价且最有效的一层：已知侵权图永远不再进人工

**审核提示要覆盖的三类场景**（文案由本工程自拟）：

- 图片审核未通过，通用驳回。
- 命中违规关键词，提示用户修改后重新提交。
- 作品被判定设计不当，提示下单风险。

### 2.2 pHash 黑名单

**感知哈希（pHash）**：对图片做感知哈希，得到 64 位整数。相似图（缩放、压缩、轻微裁剪）哈希值相近。

```sql
-- 精确命中
SELECT * FROM aud_blacklist WHERE pHash = ?;
-- 近似命中（汉明距离）
SELECT *, BIT_COUNT(pHash ^ ?) AS dist FROM aud_blacklist HAVING dist <= 5;
```

| 机制 | 说明 |
|---|---|
| 入库时机 | 判定违规的图自动入库 |
| 比对时机 | 上传时、进生产前 |
| 阈值 | 汉明距离 ≤ 5 视为同一图【推断值，需调优】 |

> **为什么值得做**：同一个爱豆的同一张图会被反复上传。第一次人工抓出来后入库，后续所有相同上传全部自动拦截——人工成本随黑名单增长而下降。

### 2.3 文本审核

敏感词表 + 命中处理：

| 动作 | 场景 |
|---|---|
| 替换 | 轻度敏感 |
| 拒绝 | 严重违规 |

适用范围：作品名、合集名、订单备注、工单内容。

### 2.4 版权承诺

**每次上传都记一条** `aud_copyright_promise`：

| 字段 | 说明 |
|---|---|
| `user_id` / `biz_type` / `biz_id` | |
| `promise_version` | 承诺书版本号 |
| `ip` | 承诺时的 IP |
| `create_time` | |

**双重作用**：

1. **合规**：用户承诺拥有图片权利或已获授权
2. **凭证**：出事时可举证「是用户承诺过的」

承诺书文本需法务确认【待确认】。

## 3. 作品状态机

| 值 | 状态 | 触发 |
|---|---|---|
| 2 | **待审核** | 新保存 / 分享前 |
| 3 | **待修改** | 审核驳回，等用户改 |
| 5 | 商品下架 | 该商品被下架 |
| 6 | **作品过期** | 超过有效期 |
| 7 | **作品违规** | 审核判定违规 |

**流转**：

```
保存 ──> 待审核 ──通过──> 正常（可分享/可下单）
            │
            ├──驳回──> 待修改 ──用户改后──> 待审核
            │
            ├──违规──> 作品违规（黑名单入库）
            │
            └──超时/下架──> 作品过期 / 商品下架
```

**「分享中不可删除」**——作品被分享码引用时，删除需先处理分享码。

**连带失效**：作品被封禁时，引用它的分享码**自动失效**，失效原因写 `关联作品已封禁`（常量 `WmsWorkService.REASON_WORK_BANNED`）。

## 4. 审核队列与分工

### 4.1 队列

```
待审队列（按优先级）
  ├─ 高：首次上传的用户
  ├─ 高：进生产前的二次确认
  ├─ 中：老用户的普通上传
  └─ 低：已通过用户的微调
```

**审核时机**：**付款后、进生产前**【已确认】。

- 付款前审会挡住正常下单体验
- 进生产后审来不及拦（已印成实物）

### 4.2 独立审核角色

**设独立「审核」角色**，理由：

- **责任留痕** —— 出侵权问题要能查到「是谁放行的」
- 客服兼任会把责任糊掉
- 审核需要专业判断（版权意识），不是谁都能干

**权限**：

| 权限 | 标识 |
|---|---|
| 查看待审队列 | `audit:image:list` |
| 放行 | `audit:image:approve` |
| 驳回 | `audit:image:reject` |
| 黑名单管理 | `audit:blacklist:manage` |

**审核结论必须记快照**（谁、何时、对哪张图、什么结论）。

## 5. UGC 作品分享的审核

「作品」是可公开分享的用户生成内容——用户把作品做成分享码发给好友/粉丝群。

**这比私下定制风险更大**：等于平台在帮用户传播可能有版权的图。

### 5.1 审核时机

**发布前审**（作品转公开分享态之前）。

### 5.2 举报入口

**不做用户举报**。

**替代方案**：侵权行为走 **后台「侵权投诉工单」**（客服受理）。

**理由**：不凭空加小程序端不存在的功能，但保留处置能力。

## 6. 侵权投诉

### 6.1 入口

走**客服工单**，`svc_ticket.type = 2`。

**投诉方可以是**：

- 权利人（版权方、经纪公司）
- 平台自身巡检发现
- 第三方举报（经客服手工建单）

### 6.2 处置流程

```
受理 ──> 核实（查作品、订单、是否为付费内容）
            │
            ├─ 成立 ──> 作品封禁 + 分享码失效 + 下架相关商品
            │           + 记录处置结论
            │
            └─ 不成立 ──> 记录理由，关闭
```

### 6.3 连带处理

作品封禁时的**自动连带**：

| 连带对象 | 处理 |
|---|---|
| 引用该作品的分享码 | **自动失效**（`关联作品已封禁`） |
| 该作品的在制订单 | **需人工决定**（已印的怎么办） |
| 该作品相关商品 | 可选下架 |

> **在制订单是难点**：图已印成实物，拦截意味着损失。本设计**不自动处理**，转人工决策并留痕——自动化的代价在这里太高。

## 7. 客服工单

### 7.1 类型

| 值 | 类型 | 说明 |
|---|---|---|
| 1 | 售后咨询 | 「我的订单到哪了」 |
| 2 | **侵权投诉** | 见上节 |
| 3 | **色差投诉** | 自印高频问题 |
| 4 | 其他 | |

### 7.2 四态流转

```
待受理 ──> 处理中 ──> 已解决 ──> 已关闭
```

**就这四态**。再细会变成流程负担，客服会绕过系统。

### 7.3 关键设计：工单可选关联订单

`svc_ticket.order_id` **可空**。

**理由**：咨询类问题常常还没下单（「你们能做多大的卡？」），强制挂订单会把这类咨询堵死——而这类恰恰是售前转化的关键。

### 7.4 建单来源

| 来源 | 说明 |
|---|---|
| 用户提交（小程序） | 主渠道 |
| **客服代客建单** | 电话/微信来的诉求 |

### 7.5 与售后的关系

| | 售后 `oms_aftersale` | 工单 `svc_ticket` |
|---|---|---|
| 目的 | 退钱 | 沟通/投诉 |
| 是否必须挂订单 | **是** | **否** |
| 状态 | 待审/通过/驳回/完成 | 四态 |

**可转换**：工单处理中发现需退款 → 客服转建售后单，工单里记录关联。

## 8. 审核相关配置项

| key | 说明 |
|---|---|
| `audit.autoRejectOnBlacklist` | 黑名单命中是否直接驳回（默认 true） |
| `audit.pHashThreshold` | pHash 汉明距离阈值（默认 5） |
| `audit.manualQueueEnabled` | 是否所有图都进人工（默认 false，仅疑似进） |
| `audit.sensitiveWordsEnabled` | 文本审核开关 |
| `workshare.auditBeforePublic` | 分享前是否必审（默认 true） |
| `workshare.expireDays` | 作品默认有效期 |

## 9. 本模块的关键判断

| 决策 | 理由 |
|---|---|
| 自动拦截 + 人工复核 | 全自动挡不住新图，全人工会累死 |
| **独立审核角色** | 责任留痕，出事要能查到谁放行的 |
| pHash 黑名单 | 同图反复上传是常态，第一层拦截成本最低 |
| 每次上传记版权承诺 | 合规要求 + 出事时的凭证 |
| **不做用户举报** | 小程序无此入口，不凭空造功能 |
| 侵权走客服工单 | 保留处置能力，不建 DMCA 式复杂工作流 |
| 在制订单不自动处理 | 已印成实物，自动化的代价太高，转人工留痕 |
| 色差只做类型不做系统 | v1 先有记录与统计，规则化留待二期 |
